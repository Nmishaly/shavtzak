# לוח שיבוץ פלוגתי — אתר מסונכרן ומוגן

הכלי מה-Artifact הפך לאתר רגיל:

- **מסונכרן** — כל השינויים נשמרים ב-Firebase Firestore ומופיעים מיד אצל כל מי שהלוח פתוח אצלו.
- **מוגן** — מי שמקבל את הקישור רואה רק כפתור **"בקשת גישה"**. הוא לוחץ פעם אחת, מתחבר עם Google, והבקשה מגיעה אליך.
  אתה מאשר **לעריכה** או **לצפייה בלבד**, והלוח נפתח אצלו מיד, בלי לרענן. הדפדפן זוכר אותו, כך שבפעם הבאה הלוח פשוט נפתח.
- ההרשאות נאכפות בשרת (`firestore.rules`), לא רק בממשק. מי שלא אושר לא יכול לקרוא את הנתונים בשום דרך, וצופה לא יכול לכתוב.

## מבנה הקבצים

| קובץ | תפקיד |
|---|---|
| `index.html` | הכלי עצמו (אותו קוד כמו ב-Artifact) |
| `gate.js` | מסך הכניסה, בקשות הגישה, פאנל ההרשאות והחיבור ל-Firebase |
| `gate.css` | עיצוב מסך הכניסה |
| `firebase-config.js` | **צריך למלא** — פרטי פרויקט ה-Firebase וכתובת המנהל |
| `firestore.rules` | **צריך למלא** — כללי האבטחה (כתובת המנהל) |
| `.github/workflows/pages.yml` | פריסה אוטומטית ל-GitHub Pages |
| `firebase.json` | לפריסה דרך Firebase Hosting (חלופה) |

## הקמה (פעם אחת, כ-15 דקות)

### 1. פרויקט Firebase (חינם)
1. נכנסים ל-<https://console.firebase.google.com> ויוצרים פרויקט חדש (Analytics לא נחוץ).
2. **Build › Authentication › Get started › Sign-in method** — מפעילים **Google**.
3. **Build › Firestore Database › Create database** — מצב **Production**, אזור `me-west1 (Tel Aviv)` או `europe-west1`.
4. **Project settings (גלגל השיניים) › General › Your apps** — לוחצים על `</>` (Web), נותנים שם, ומעתיקים את אובייקט `firebaseConfig`.

### 2. מילוי ההגדרות בריפו
1. ב-`firebase-config.js` — מדביקים את הערכים במקום `REPLACE_ME`, ובשורה `OWNER_EMAIL` כותבים את כתובת הג'ימייל שלך.
2. ב-`firestore.rules` — מחליפים את `OWNER_EMAIL_HERE` באותה כתובת, **באותיות קטנות**.
   (ערכי `firebaseConfig` אינם סודיים. מה שמגן על הנתונים הוא כללי האבטחה.)

### 3. פרסום כללי האבטחה
ב-Firebase Console: **Firestore Database › Rules** — מוחקים את מה שיש, מדביקים את כל התוכן של `firestore.rules` (אחרי ההחלפה) ולוחצים **Publish**.

### 4. העלאת האתר — אחת משתי האפשרויות
**א. GitHub Pages (אוטומטי):**
1. בריפו ב-GitHub: **Settings › Pages › Source: GitHub Actions**.
2. כל push לענף הראשי מפרסם את האתר בכתובת `https://<user>.github.io/shavtzak/`.
   > בחשבון GitHub חינמי, Pages עובד רק בריפו ציבורי. זה בסדר: בריפו יש רק קוד, ונתוני הפלוגה נשמרים ב-Firebase מאחורי ההרשאות. אם הריפו חייב להישאר פרטי, השתמשו באפשרות ב'.

**ב. Firebase Hosting:**
```bash
npm install -g firebase-tools
firebase login
firebase use --add          # בוחרים את הפרויקט
firebase deploy             # מעלה את האתר וגם את כללי האבטחה
```
הכתובת תהיה `https://<project-id>.web.app`.

### 5. אישור הדומיין להתחברות
**Authentication › Settings › Authorized domains › Add domain** — מוסיפים את הדומיין של האתר, למשל `nmishaly.github.io`.
(`<project-id>.web.app` כבר מאושר מראש.)

### 6. העברת הנתונים מה-Artifact
1. נכנסים לאתר ולוחצים "בקשת גישה" עם חשבון המנהל. המנהל נכנס מיד, בלי אישור.
2. **הרשאות › גיבוי ושחזור נתונים › ייבוא מקובץ גיבוי** — בוחרים את הקובץ `shavtzak-backup-from-artifact.json` (נשלח בנפרד ולא נשמר בריפו כי יש בו שמות).

## שימוש יומיומי
- **שיתוף:** הרשאות › "העתק קישור לשיתוף" ושולחים בוואטסאפ.
- **אישור:** כשיש בקשה חדשה, ליד כפתור "הרשאות" מופיע מספר אדום. בוחרים "אשר לעריכה", "אשר לצפייה" או "דחה".
- **שינוי או ביטול גישה:** אפשר לשנות בכל רגע. אצל המשתמש הדף מתעדכן מיד (וגישה שבוטלה נסגרת).
  "מחק" מוחק את הרשומה ומאפשר למשתמש לבקש גישה שוב.
- **גיבוי:** הרשאות › "הורד גיבוי (JSON)". מומלץ לעשות מדי פעם.

## הערות
- **וואטסאפ / אינסטגרם:** Google חוסמת התחברות מתוך הדפדפן הפנימי של אפליקציות. אם הקישור נפתח שם, האתר מציג הודעה שמבקשת לפתוח אותו ב-Chrome או ב-Safari.
- הלוח שומר עותק מקומי, כך שבקליטה חלשה הוא עדיין נפתח עם הנתונים האחרונים, ושינויים נשלחים כשהחיבור חוזר.
- קבצי גיבוי (`*backup*.json`) מוחרגים ב-`.gitignore` כדי ששמות החיילים לא יעלו לריפו.
